## 📖 今日核心知识（生活化解释）

1. **一次遍历，多件事一起干**
   想象你是超市收银员，一批商品从传送带上经过，你**只扫一遍**，但同时记录：总共几件、最贵的是哪件、有没有过期商品。算法里叫"单趟扫描（one-pass）"——数组只走一次，边走边更新多个"记录本"。这是效率和优雅的来源。

2. **"计数数组 / 哈希思想"的雏形**
   统计"每个数字出现了几次"，最笨的办法是每个数都去数一遍（O(n²)）；聪明的办法是**开一个"登记本"**，数字几就翻到第几页 +1。这就是后面哈希表、桶排序的祖宗。

3. **边界条件 = 代码的照妖镜**
   算法题 80% 的 bug 不在主逻辑，在边界：空数组、只有一个元素、全相同、全负数。写代码前先问自己三句话：**"最小规模是什么？""极端输入是什么？""我的初始值设对了吗？"**

## 💻 今日实战任务（必须手写，禁止AI代写）

> **题目：数组中数字的出现次数（LeetCode 风格入门题）**
>
> 给定一个长度为 `n`（1 ≤ n ≤ 1000）的整数数组 `nums`，数组元素范围是 `0 ≤ nums[i] ≤ 100`。
> 请找出**出现次数最多的数字**；如果有多个数字出现次数相同且都是最多，**输出其中最小的那个数字**。
>
> **输入示例**：
> ```
> 7
> 3 1 3 2 3 1 1
> ```
> **输出示例**：
> ```
> 1
> ```
> （解释：1 出现 3 次，3 出现 3 次，次数并列最多，取较小的 1。）

**要求（一条都不能少）**：
1. **必须手写**，从 `#include <stdio.h>` 开始，不许复制粘贴、不许问 AI 要代码。
2. 用**一次遍历**的思路来完成（提示：那个"登记本"知识点用得上）。
3. 代码里加注释，写清你每一步在干什么——**注释是给你未来的自己看的**。
4. 写完自己造 **3 组测试数据**（至少要包含：全相同、次数并列、n=1 三种情况），跑通再提交。
5. 卡住超过 15 分钟可以来看我给的**思路提示**（在下面折叠区），但**先自己憋 15 分钟**。

<details>
<summary>👉 实在卡住了？点开看思路提示（先别看！）</summary>

- 思路：开一个大小为 101 的数组 `count[101] = {0}`，当作"登记本"，`count[x]` 表示数字 x 出现了几次。
- 第一趟：遍历 `nums`，读到数字 x 就 `count[x]++`。
- 第二趟：从 0 到 100 扫一遍 `count`，记录"当前最大次数"和"对应数字"，注意"次数相同取较小数字"→ 因为是从小到大扫，**用 `>`（严格大于）更新即可**，遇到相等不更新，天然保留较小者。
- 边界：n=1 时答案就是那个数本身，你的逻辑要能覆盖。
